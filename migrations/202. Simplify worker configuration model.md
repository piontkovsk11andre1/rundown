# Simplify worker configuration model

The current worker model has too many routing concepts: `workers.default`, `workers.tui`, `workers.fallbacks`, `commands.*`, harness presets, and command-specific worker overrides. The target model keeps token-array worker commands but simplifies routing around default, interactive, profiles, and fallbacks. Existing persisted config should be handled deliberately during the migration.

- [x] Replace the current worker routing model with a smaller schema: keep token-array commands, rename `workers.tui` to `workers.interactive`, remove `commands.*`, and remove command-specific worker config for deleted commands.
- [x] Define retained command routing explicitly: `run`, `all`, `materialize`, `plan`, `make`, `do`, `add`, `reverify`, and `undo` use `workers.default`; `repair` and `discuss` prefer `workers.interactive` and fall back to `workers.default` when needed; `profile=<name>` uses `profiles.<name>`.
- [x] Rework fallbacks into an explicit backup-worker model, such as `fallbacks.default` and optionally `fallbacks.<profile>`, instead of mixing fallback routing into `workers.*`.
- [x] Update terminology across config, help, presets, tests, and TUI from `harness`/`tui worker`/command worker wording to `provider`, `worker`, `interactive worker`, `profile`, and `fallback`.
- [x] Update `with <provider>` so it only configures workers/profiles/fallbacks from provider presets and does not auto-open the TUI or perform other side effects.
